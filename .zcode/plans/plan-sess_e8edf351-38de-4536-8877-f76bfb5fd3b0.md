## 目标
在不迁移到新引擎、不中断现有离线玩法的前提下，提升植被与敌人的真实感，彻底统一坦克/直升机的座舱视角与射击方向，并补上可重复的自动/边界测试。保留当前未提交的 `index.html` 版本号更新和 `js/player.js` 直升机视角修复，不覆盖或回退它们。

## 1. 先建立基线并保护现有改动
- 记录当前 `git diff`，确认只在现有改动基础上增量修改。
- 用本地静态服务器打开游戏，采集标题、战斗、森林/水域、坦克、直升机几个基线截图，并记录浏览器控制台错误。
- 用现有 `window.__dbg()` 作为运行状态基线；不把当前 `?v=9` 缓存参数改回旧值。

## 2. 植被与地面真实感升级（主要修改 `js/terrain.js`，必要时配合 `js/world.js` / `js/scene.js`）
### 树
- 将树冠、云杉、枯树和树干/分叉几何改成真正的共享缓存；同一种几何只生成一次，区块只保存实例矩阵，区块卸载时不销毁仍被其他区块使用的共享几何。
- `plantTrees()` 改为按每棵树的局部 `biomeW(wx,wz)` 选择树种，而不是使用区块中心的单一风格，避免沙漠区刷出整片阔叶树、混合地貌边缘突然换树。
- 增加树间距、坡度和水边过滤，并让树冠/树干高度依据实际地形点对齐；为不同树种/年龄加入高度、偏转、冠幅和绿色色相变化。
- 在现有低多边形成本可控的前提下加入少量主枝/分叉轮廓、程序化树皮颜色/法线/粗糙度变化；不把每棵树拆成大量独立 Mesh。
- 修正实例色彩目前只有灰度缩放的问题，使用有范围的绿/黄/枯褐色相变化，同时保持 `InstancedMesh` 批处理。

### 草
- 把当前两个交叉矩形面片替换为 3–5 种共享的弯曲/交叉草叶几何；增加草叶 UV 和程序化 alpha 纹理，使用 `alphaTest + depthWrite`，避免透明混合排序导致闪烁。
- 按地貌和距离设置草色、密度、高度随机化，加入轻量顶点风摆动（使用 Three.js r128 支持的 `onBeforeCompile`，不引入新引擎）；近处少量草接收/投射阴影，远处关闭阴影。
- 给草与树增加距离等级：近处完整细节，中距离降密度/关闭阴影，远处仅保留低成本轮廓，避免把“更逼真”变成掉帧。

### 区块和渲染生命周期
- 为植被/道具实例设置正确的区块包围体和距离可见性，移除无条件 `frustumCulled=false` 带来的远处和阴影通道浪费；对不能安全自动剔除的实例使用按区块的可见性开关。
- 修正 `buildChunk()`/卸载逻辑：不再 dispose 全局共享的 `GRASS_GEO`、岩石/树冠几何，也不把已 dispose 的地面几何重新放回缓存；只释放区块独占的材质和几何。
- 在 `js/scene.js` 保留 ACES、SSAO、Bloom、FXAA、PMREM 管线，不重复做 Gamma；只调整树草的阴影偏差、雾的远景对比度和必要的近景光照。
- 在 `js/main.js` 把自适应画质统计改为只统计实际游戏渲染帧，并增加植被质量等级（草密度、树阴影、风摆动）降档；避免标题/暂停状态误触发降档。能恢复时平滑恢复，不在玩家操作中突然跳档。

## 3. 敌人模型升级（主要修改 `js/models.js`，小量修改 `js/enemy.js`）
- 保留现有迷彩纹理、AK 轮廓和骨骼动画，避免换成无法离线加载的外部模型。
- 为普通步兵、枪手、重装兵、BOSS 做可识别但共享资源的装备轮廓：头盔/护目镜/下颌与颈部、战术背心和弹匣袋、肩/膝护具、背包/水壶/枪带等，使用共享几何+实例/材质变体控制成本。
- 给布料、头盔、金属、枪托补更合理的粗糙度/法线和细微色差；减少纯塑料感，保持敌人在森林/焦土/雪地背景中的可辨识度。
- 修正/加固敌人正面朝向和持枪 IK 的边界（不同缩放、近距离、转身时不穿模），并在敌人更新中保留巡逻/警戒行为，不改变现有玩法节奏。

## 4. 坦克/直升机座舱视角与武器对齐（主要修改 `js/drops.js`、`js/player.js`）
- 为每种载具定义真实的座椅/座舱锚点，不再用“玩家眼高 + 固定大偏移”：坦克锚点放在炮塔舱盖内，直升机锚点放在驾驶舱内并随 `vehicle.alt` 和机体位置更新。
- 新增统一的 `getVehicleViewPosition()`/等价辅助函数，让 `eyeY()`、`updateCamera()`、敌人命中高度和载具开火使用同一个视点，消除“镜头位置和子弹起点不一致”。
- 进入载具时锁定玩家与载具坐标同步；离开/载具被击毁时把玩家移到安全侧后方、清零飞行高度并恢复无载具枪械视图，防止残留高度或第一人称武器隐藏状态。
- 让坦克炮塔 yaw、直升机机炮方向和准星方向统一使用相机的 yaw/pitch；修复炮弹/机炮在上下瞄准、地形坡度和载具旋转后偏离准星的问题。保留已有的载具冷却递减修复，并增加重复开火回归检查。
- 在视点落点附近加入最小安全距离/地形夹紧，保证载具停在坡地、水边或卸载后不会把相机放入地形、水面或机体外。

## 5. 自动测试与边界测试（新增 `tests/`，不引入构建工具）
- 新增无依赖的浏览器测试页（例如 `tests/runner.html` + `tests/runner.js`），通过 `index.html?test=1` 加载游戏并读取受控的测试 API；生产页面不显示测试 UI。
- 自动断言：启动无空白/无未捕获异常、关键全局状态和相机坐标均为有限数、区块生成/卸载后仍可渲染、树草共享几何未被错误 dispose、地形/水面边界值稳定。
- 载具回归断言：坦克和直升机分别进入/退出；座舱锚点在预期高度范围且不埋地/漂浮；相机朝向与载具射击方向一致；连续多次开火冷却会恢复而不是只打一发；被击毁后不会残留 `vehicleKind`、飞行高度或幽灵载具。
- 玩法边界断言：水面边界、最低/最高地形高度、极端 yaw/pitch、坡地移动、连续区块流式移动、无敌/溺水计时和重复拾取不产生 NaN、卡死或越界。
- 在 `tests/README.md` 写明运行方式：`python3 -m http.server`（或现有静态服务器）后打开测试页；测试页显示通过/失败明细和总数，便于以后回归。

## 6. 浏览器黑盒验收
- 自动测试通过后，用真实 GUI 操作验证：标题→出击→战斗、森林/草地近景、敌人正面/侧面、靠近空投→乘坦克/直升机→移动/转视角→开火→下车。
- 重点观察截图：树冠/树干是否连贯、草是否仍像重复矩形、敌人是否可辨识、坦克视点是否在舱内、直升机视点是否随爬升而不是站在旋翼上方。
- 收集控制台 error/warn 和截图证据；若性能不足，优先通过植被等级/阴影/实例剔除优化，不盲目引入重型后处理。

## 7. 库/插件结论与文档
- 第一阶段不替换 Three.js：仓库没有 `tree.js`；当前 Three.js r128 已有 `InstancedMesh`、LOD、Shader `onBeforeCompile`、PMREM、SSAO/Bloom/FXAA，足以解决本次问题，而且保持离线、零构建、零网络资源。
- 在 README 技术建议中补充可选升级路线：需要高质量资产时用 `GLTFLoader` + Draco/Meshopt/KTX2；需要大量地形射线/碰撞时可评估 `three-mesh-bvh`；只有要真实刚体车辆物理时才考虑 Rapier。它们不作为本次必需依赖，避免破坏当前静态离线交付。
- 只有在这轮测试稳定后，才单独评估从 r128 升级现代 Three.js；不把版本迁移与植被/载具修复混在同一变更中。
